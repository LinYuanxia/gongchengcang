## 2. 功能定位

**工程仓端销项发票 = 供应商端发票管理（功能一致）**

| 角色 | 开票方向 | 关联单据 | 参考实现 |
|------|---------|---------|---------|
| 供应商端 | 供应商 → 工程仓（采购订单） | 已完成采购订单 | [index.vue](file:///Users/mcdreamy/Documents/trae_projects/gongchengcang2/apps/pc/src/views/supplier/finance/invoice/index.vue) |
| 工程仓销项 | **工程仓 → 施工方（销售订单）** | 已完成销售订单 | 本次建设，对齐供应商端 |

核心差异仅在于：供应商端选择**采购订单**，工程仓销项选择**已完成销售订单**。其余功能完全一致。

## 6. 弹窗设计（核心）

申请开票和行开票共用**同一个弹窗**，差异仅在于是否显示订单选择器：

```
┌──────────────────────────────────────────────────────────────────┐
│ 开具发票                                                    [X] │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│ ⓘ 请上传发票文件完成开票，仅支持上传发票文件，不支持在线开票       │
│                                                                  │
│ ↓↓↓ 以下区域仅在「申请开票」时显示，行开票时隐藏/禁用填充 ↓↓↓     │
│ ┌──────────────────────────────────────────────────────────────┐ │
│ │ *关联销售订单：[▼ 请选择已完成销售订单___________________]    │ │
│ └──────────────────────────────────────────────────────────────┘ │
│                                                                  │
│ *票据类型：[专票] [普票]                                          │
│                                                                  │
│ 订单编号：[SO202401100001]  (已关联，自动填充或通过选单带入)     │
│ 施工方：  [中建一局集团]          (从订单自动带入)               │
│ 开票金额：[650,000.00]           (等于订单金额或可开票金额)      │
│                                                                  │
│ *发票号码：[________________]  (OCR成功后自动填充)               │
│ *发票抬头：[中建一局集团]        (从订单自动带入)                │
│ *纳税人识别号：[________________]                                │
│                                                                  │
│ *发票文件：[📎 上传发票文件] 支持PDF/JPG/PNG ≤10MB              │
│           上传后自动OCR识别                                      │
│                                                                  │
│ ↓↓↓ OCR识别结果区域（上传后展示） ↓↓↓                            │
│ ┌──────────────────────────────────────────────────────────────┐ │
│ │ ✅ OCR识别合格 或 ❌ 识别失败/金额不一致/数量不一致           │ │
│ │ ┌─ 识别金额: ¥650,000 ✅ 金额一致                          │ │
│ │ │ 发票号: 00987654 | 开票日期: 2024-01-15                  │ │
│ │ │ 销售方: XX公司 | 购方: 中建一局                         │ │
│ │ └─ 商品明细: 3项  ✅ 数量一致                             │ │
│ └──────────────────────────────────────────────────────────────┘ │
│                                                                  │
│ 备注：[________________________]                                 │
│                                                                  │
│                              [取消]    [确认开票]                │
└──────────────────────────────────────────────────────────────────┘
```

**关键逻辑**：
- **申请开票**：顶部显示「关联销售订单」下拉选择器，选单后自动回填订单信息
- **行开票**：不显示选单器，直接使用当前记录的关联订单信息，订单编号/施工方/金额字段 disabled
- **两种入口最终进入同一个Modal**，通过 `props/参数` 控制是否展示选单区域

## 7. 数据模型

### 7.1 接口定义

```typescript
// 发票主记录（与供应商端 SupplierInvoice 保持一致）
interface InvoiceRecord {
  id: string
  orderNo: string              // 关联销售订单号
  invoiceNo: string            // 发票号码（上传后填充）
  invoiceTitle: string         // 发票抬头（=施工方名称）
  invoiceAmount: number        // 开票金额（=订单可开票金额）
  actualInvoiceAmount?: number // 实际开票金额（上传时填写）
  invoiceStatus: 'pending' | 'done' | 'voided'
  taxType: 'special' | 'general'  // 票据类型
  invoiceFile?: string         // 发票附件URL
  invoiceTime?: string         // 开票时间
  voidReason?: string          // 作废原因
  voidCount?: number           // 作废次数（≤1）
  createTime: string
  orderItems?: OrderItem[]     // 订单商品明细（OCR核对用）
}

interface OrderItem {
  productName: string
  quantity: number
  unit: string
  unitPrice: number
  amount: number
}

// 销售订单（用于申请开票选单）
interface SalesOrder {
  id: string
  orderNo: string
  buyerName: string            // 施工方名称=购方
  totalAmount: number          // 订单总金额
  invoicedAmount: number       // 已开票金额
  availableAmount: number      // 可开票金额 = totalAmount - invoicedAmount
  createTime: string
  items: OrderItem[]           // 商品明细
}

// OCR状态与结果（与供应商端一致）
type OcrState = 'pending' | 'recognizing' | 'success' | 'failed'

interface OcrResult {
  recognizedAmount: number
  recognizedQuantity: number
  invoiceNo: string
  invoiceCode: string
  invoiceDate: string
  sellerName: string           // 销售方（工程仓）
  buyerName: string            // 购方（施工方）
  items: OrderItem[]
  amountMatch: boolean
  quantityMatch: boolean
  qualified: boolean           // amountMatch && quantityMatch
}
```

## 8. 详细功能规格

### 8.1 申请开票（顶部按钮）

| 项目 | 说明 |
|------|------|
| 入口 | 列表顶部「申请开票」按钮 |
| 触发器 | 点击弹出开具发票Modal，显示「关联销售订单」选择器 |
| 选单 | Select下拉，展示所有 `availableAmount > 0` 的已完成销售订单 |
| 选择后 | 自动回填：订单编号(disabled)、施工方(disabled)、开票金额(=availableAmount) |
| 后续 | 与行开票弹窗完全一致，填写发票信息→上传文件→OCR→确认提交 |
| 取消 | 关闭弹窗，不保存任何数据 |

### 8.2 行开票（列表中操作）

| 项目 | 说明 |
|------|------|
| 入口 | 列表中 `status=pending` 的记录行，操作列「开票」按钮 |
| 弹窗 | 与申请开票共用一个Modal，但**不显示选单器** |
| 预填充 | 订单编号、施工方、开票金额 = 当前记录的值，全部disabled |
| 后续 | 填写发票信息→上传文件→OCR→确认提交 |

### 8.3 OCR识别（与供应商端一致）

| 步骤 | 说明 |
|------|------|
| 触发 | 选择发票文件后自动触发 |
| 过程 | 进度条展示 "OCR识别中，请稍候..." |
| 成功 | 展示识别结果（金额+商品明细），自动填充发票号码和金额 |
| 校验 | 金额一致 + 商品数量一致 → `qualified: true` |
| 失败 | 展示失败页，"未能识别发票上的有效信息，请重新上传" |
| 提交条件 | 仅 `ocrState === 'success' && ocrResult.qualified === true` 时可提交 |

### 8.4 作废发票

| 项目 | 说明 |
|------|------|
| 条件 | 仅 `status === 'done' && voidCount < 1` |
| 入口 | 列表操作列 + 查看详情弹窗底部 |
| 确认 | 弹窗确认，Alert提示"每张发票仅允许作废1次" |
| 原因 | 选填 Textarea，maxLength=200 |
| 结果 | `status='voided'`, `voidCount+=1`, 记录作废时间 |
| 异常 | 已达上限时阻断，Message.error 提示 |

### 8.5 重新开票

| 项目 | 说明 |
|------|------|
| 条件 | 仅 `status === 'voided'` |
| 逻辑 | 复制原记录的订单信息，创建新 `pending` 记录（新id），原作废记录保留 |
| 结果 | 新记录出现在列表中，可重新走开票流程 |
| 限制 | 原作废记录的voidCount=1，不可再操作；

### 8.6 查看详情

弹窗展示：订单号、发票抬头、开票金额/实际开票金额、票据类型、发票号、开票时间、状态、作废原因、发票附件预览+下载。

### 8.7 下载附件

已开票记录操作列 + 详情弹窗中提供下载按钮。

## 9. 异常边界与容错

| 场景 | 系统行为 | 提示信息 |
|------|---------|---------|
| 无可选销售订单 | 下拉列表为空 | 无可用提示（所有订单已全额开票） |
| OCR识别失败 | 展示失败页+重新上传按钮 | "未能识别发票上的有效信息，可能是图片不清晰或格式不正确" |
| OCR金额不一致 | 红色Tag标注，不可提交 | "识别金额与订单金额不一致" |
| OCR数量不一致 | 红色Tag标注，不可提交 | "商品数量与订单不符，请核对后重新上传发票" |
| 重复作废 | 阻断操作 | "该发票已达到最大作废次数（1次），无法再次作废" |
| 文件格式错误 | 前端阻止 | — |
| 文件超10MB | 前端阻止 | — |

## 10. 进度统计规则

| 统计项 | 计算逻辑 |
|--------|---------|
| 待开票金额 | `invoiceList.filter(i => i.status === 'pending').reduce(sum, i.amount, 0)` |
| 待开票笔数 | `invoiceList.filter(i => i.status === 'pending').length` |
| 已开票金额 | `invoiceList.filter(i => i.status === 'done').reduce(sum, i.actualInvoiceAmount, 0)` |
| 本月开票笔数 | `invoiceList.filter(i => i.status === 'done' && isThisMonth(i.invoiceTime)).length` |
