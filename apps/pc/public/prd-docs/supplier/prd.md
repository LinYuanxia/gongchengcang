## 一、系统概述与技术架构

### 1.1 项目定位

供应商端是**工程仓采供一体化平台**的供应商门户子系统，为材料供应商提供商品管理、订单履约、发货管理、财务对账等核心业务能力。供应商通过本系统实现"接单→发货→结算"的全链路数字化管理。

### 1.2 技术架构

| 维度 | 选型 |
|------|------|
| 框架 | Vue 3 (Composition API + `<script setup>`) |
| 语言 | TypeScript |
| UI组件库 | Arco Design Vue 2.x |
| 状态管理 | Pinia |
| 路由 | Vue Router 4 |
| 构建工具 | Vite 5 |
| 包管理 | pnpm workspace (monorepo) |
| 公共包 | `@gongchengcang/types` `@gongchengcang/utils` `@gongchengcang/api` `@gongchengcang/constants` |

### 1.3 供应商端在整个系统中的定位

| 能力维度 | 供应商端 | 平台端 | 工程仓端 |
|---------|:--------:|:------:|:--------:|
| 商品定义（分类/SPU/SKU） | ❌ 消费平台商品 | ✅ 定义标准商品 | ❌ 消费 |
| 供货价格设置 | ✅ 设置供货价 | ✅ 审核 | ❌ 不可见 |
| 订单确认/发货 | ✅ 接单+发货 | ❌ 只读 | ❌ 采购方 |
| 全平台订单查看 | ❌ 仅自己 | ✅ 全量 | ❌ 仅自己 |
| 商品审核 | ❌ 不可 | ✅ 审核 | ❌ 不可 |
| 售后补发管理 | ✅ 处理补发 | ❌ 不可 | ❌ 不可 |
| 发票管理 | ✅ 上传开票 | ✅ 审核 | ❌ 不可 |

## 二、术语表

| 术语 | 说明 |
|------|------|
| **供应商** | 建材供货企业，在平台上向工程仓提供商品 |
| **采购订单** | 工程仓→供应商的采购单据 |
| **SPU** | 标准产品单元（商品聚合），如"立邦漆5L白色" |
| **SKU** | 库存量单位（具体售卖规格），如"立邦漆5L白色/哑光" |
| **供货价** | 供应商为商品设定的销售价格，仅工程仓可见 |
| **供货状态** | 供应商商品的供货控制：供货中/暂停供货/永久停货 |
| **审核状态** | 商品审核状态：待审核/已通过/已驳回 |
| **上架状态** | 商品在工程仓是否可见：已上架/已下架 |
| **补发** | 货损/售后后供应商重新发货的处理流程 |
| **OCR识别** | 发票图片光学字符识别，自动提取发票信息 |
| **结算单** | 供应商与平台按周期结算的对账单 |

**OCR识别功能**：

1. 上传发票文件或图片后自动触发OCR识别
2. OCR状态流转：`pending(初始)` → `recognizing(识别中)` → `success(识别成功)` / `failed(识别失败)`
3. 识别中状态：展示进度条 + loading动画
4. 识别成功后展示识别结果面板：
   - 识别金额、发票代码、发票号码、开票日期、销售方、购买方
5. **商品明细核对**（可折叠面板）：
   - 发票商品明细 vs 订单商品明细 对比展示
   - 金额一致性校验：识别金额与订单金额是否一致
   - 数量一致性校验：发票数量与订单数量是否一致
6. OCR结果Alert提示：合格(绿色) / 不合格(红色)

**TypeScript接口定义**：
```typescript
interface OcrState {
  status: 'pending' | 'recognizing' | 'success' | 'failed'
  progress: number
  result: OcrResult | null
}

interface OcrResult {
  amount: number
  invoiceCode: string
  invoiceNo: string
  invoiceDate: string
  sellerName: string
  buyerName: string
  items: Array<{ name: string; quantity: number; price: number }>
}
```
