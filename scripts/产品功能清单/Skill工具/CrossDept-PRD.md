## 四、执行步骤（必须按顺序执行）

### 第1步：识别涉及部门与系统
```text
1.1 扫描代码中的API调用、MQ消息、定时任务

```

### 第2步：提取跨部门交互流程
```text
2.1 找到跨系统调用的代码位置
2.2 追踪完整调用链（从请求发出到响应返回）
2.3 输出：跨部门泳道图 + 职责矩阵
```

### 第3步：提取接口契约
```text
3.1 从Controller提取对外提供的接口
3.2 从HTTP/Feign Client提取依赖的外部接口
3.3 输出：接口总览表 + 每个接口的详细定义
```

### 第4步：识别数据流向
```text
4.1 识别跨部门共享的数据实体
4.2 识别主数据源（哪个系统是权威来源）
4.3 输出：共享数据字典
```

### 第5步：识别分布式事务场景 ⭐新增
```text
5.1 扫描跨服务调用的写操作
5.2 识别是否涉及多数据源写入
5.3 判断现有事务处理方式（@Transactional/MQ重试/补偿代码）
5.4 输出：一致性方案
```

### 第6步：识别鉴权方式 ⭐新增
```text
6.1 扫描Feign/HTTP Client的请求头
6.2 识别是否携带Token/Signature/AK
```

### 第7步：推断排期与风险
```text
7.1 根据接口复杂度和依赖关系推断合理排期
     - 简单接口（CRUD，<5字段）：3天
     - 中等接口（业务逻辑，5-15字段）：5天
     - 复杂接口（多系统聚合，>15字段/需计算）：10天
7.2 识别关键路径上的依赖和风险
7.3 输出：甘特图 + 交付物清单 + 风险表
```

### 第8步：生成测试与沟通机制
```text
8.1 根据流程和接口生成联调计划
8.2 根据风险等级设计升级机制
8.3 输出：验收标准 + 沟通机制
```

#### 7.1 分布式事务场景识别

| 场景编号 | 场景描述 | 涉及服务/数据源 | 触发代码位置 |
|---------|---------|---------------|-------------|
| [SC-01] | [如：订单创建后扣减库存] | 订单服务、库存服务 | [XXService.java:123] |

**识别规则**：
- 扫描`@Transactional` + 跨服务调用（Feign/RestTemplate）
- 扫描MQ发送 + 本地数据库写入的组合
- 扫描多表/多数据源写入操作

#### 7.2 一致性方案选择

| 场景 | 选择方案 | 理由 | 容忍不一致时长 |
|------|---------|------|--------------|
| [SC-01] | 最终一致性（MQ） | 不需要强一致，用户可接受短暂延迟 | ≤5秒 |

**方案说明**：
- **TCC（Try-Confirm-Cancel）**：强一致性，适合核心资金流
- **最终一致性（MQ）**：高吞吐，适合普通业务
- **本地消息表**：可靠性最高，适合关键但非实时场景
- **最大努力通知**：适合外部系统回调

### 8. 跨系统鉴权与安全策略 ⭐新增

#### 8.1 鉴权方式总览

| 接口/系统 | 鉴权方式 | 关键凭证 | 有效期 | 获取方式 |
|---------|---------|---------|--------|---------|
| 部门A → 部门B（/api/xxx） | OAuth2 Client Credentials | client_id + client_secret | 2小时 | 从配置中心获取 |
| 部门C → 部门D（/api/yyy） | AK/SK + 签名 | AccessKey + SecretKey | 永久（定期轮换） | 线下分发 |

**常见鉴权方式**：
- **OAuth2**：标准授权，适合内部服务
- **AK/SK + 签名**：防篡改，适合开放平台
- **IP白名单**：简单有效，适合内网调用
- **JWT**：无状态，适合前后端分离

#### 8.2 Token传递链路

```mermaid
sequenceDiagram
    participant A as 前端
    participant B as 网关/BFF
    participant C as 服务A
    participant D as 服务B
    
    A->>B: 请求 + JWT Token
    B->>B: 验证JWT，提取用户身份
    B->>C: 转发 + 内部Token（x-user-id）
    C->>D: Feign调用 + 透传内部Token
```

**规则**：从代码中扫描请求头传递逻辑，自动生成Token传递链路图。

#### 8.3 敏感字段脱敏规则

| 字段名 | 敏感类型 | 脱敏规则 | 适用场景 |
|--------|---------|---------|---------|
| phone | 个人手机号 | 中间4位 `****`：`138****1234` | 日志、响应（非必要不返回） |
| idCard | 身份证号 | 保留前6后4：`440301******1234` | 日志、响应 |
| bankCard | 银行卡号 | 保留后4位：`****1234` | 日志、响应 |

**规则**：扫描DTO中的`@Sensitive`注解或字段名匹配（phone/mobile/idCard/bankCard/password等），自动生成脱敏规则。

#### 8.4 接口限流与熔断策略

| 接口 | 方向 | 限流阈值 | 熔断条件 | 降级方案 |
|------|------|---------|---------|---------|
| /api/order/create | 调用方 → 被调方 | 100 QPS | 错误率>50%持续10秒 | 返回兜底提示"系统繁忙" |

**规则**：扫描`@SentinelResource`、`@HystrixCommand`或配置中心限流配置。

## 六、代码分析规则（增强版）

### 规则1：识别外部系统调用
```text
扫描目标：
- @FeignClient（Spring Cloud）
- @RestTemplate / WebClient
- HTTP客户端（OkHttp、Apache HttpClient）
- MQ消息发送（@RabbitTemplate、@KafkaTemplate）
- 定时任务调用的外部接口

输出格式：
外部系统名称 = [从URL或服务名提取]
调用接口 = [API路径]
调用场景 = [从方法名推断]
```

### 规则2：识别接口契约
```text
从以下位置提取：
- Controller方法的@RequestMapping、@PostMapping等
- Feign Client的@RequestLine、@RequestMapping
- DTO/VO类的字段定义

输出格式：
接口路径 = [URL]
请求方法 = [GET/POST/PUT/DELETE]
请求参数 = [字段名+类型+必填]
响应结构 = [字段名+类型+说明]
```

### 规则3：识别数据流向
```text
扫描目标：
- 实体类关联关系（@OneToMany、@ManyToOne）
- 跨服务的数据传递（DTO字段）
- 缓存Key的设计（Redis）

输出格式：
主数据实体 = [实体名]
权威系统 = [哪个系统写入]
消费系统 = [哪些系统读取]
```

### 规则4：识别异常与回退
```text
扫描目标：
- try-catch块中的降级逻辑
- @SentinelResource的fallback
- retry配置

输出格式：
异常场景 = [触发条件]
系统行为 = [代码中的处理逻辑]
用户提示 = [错误消息]
```

### 规则5：识别分布式事务 ⭐新增
```text
扫描目标：
- @Transactional + 跨服务调用
- MQ发送 + 本地写操作（可能的事务消息）
- 多数据源操作（@Transactional(transactionManager="...")）

输出格式：
场景 = [操作描述]
涉及资源 = [服务A.表1, 服务B.表2]
当前处理 = [全无/@Transactional/MQ/补偿代码]
风险提示 = [若当前处理不完整，标注⚠️]
```

### 规则6：识别鉴权方式 ⭐新增
```text
扫描目标：
- Feign拦截器（@Bean的RequestInterceptor）
- RestTemplate的拦截器/请求头设置
- Gateway/Filter中的Token校验逻辑

输出格式：
鉴权方式 = [从代码逻辑推断]
凭证字段 = [Authorization/AccessKey/Signature]
获取来源 = [配置中心/环境变量/硬编码]
```

## 八、特殊情况处理

| 情况 | 处理方式 |
|------|---------|
| 代码中无外部调用（单系统项目） | 输出"单系统项目，无需跨部门协同"，建议合并到普通PRD |
| 外部系统无法识别归属部门 | 标注"⚠️ 待确认部门：[系统名]，建议联系[技术负责人]" |
| 接口无文档、无示例 | 根据字段定义推断JSON结构，标注"⚠️ 待确认" |
| 无明确排期信息 | 按复杂度公式自动生成，标注"建议" |
| 用户未提供干系人信息 | 用"[待指定：部门名]"占位，信息状态列标注⚠️，超过3项阻塞输出 |
| **⭐新增** 无非事务场景 | 第7章标注"✅ 经扫描未发现分布式事务风险" |
| **⭐新增** 无鉴权逻辑 | 第8章标注"⚠️ 未检测到鉴权逻辑，建议确认是否需要补充" |
