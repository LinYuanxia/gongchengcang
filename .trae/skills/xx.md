# 供应商端 — 售后管理（审核）功能规划方案

## 一、功能定位

**供应商端售后管理**是供应商审核和处理工程仓发起的售后申请的管理后台。当工程仓在采购订单中发起物流售后（如运输破损、数量缺失等），供应商在此功能模块中进行 **审核、补发、拒绝** 等操作。

核心角色：**审核方**（非发起方）

---

## 二、状态流转

```
┌─────────────────────────────────────────────────────────────────┐
│                        售后状态流转（供应商视角）                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   工程仓发起申请       供应商审核          供应商补发/完结           │
│  ┌─────────┐     ┌───────────┐     ┌──────────────────┐         │
│  │  申请中   │────▶│  审核通过   │────▶│   已完成（补发）   │         │
│  │ (applying)│     │ (approved) │     │   (completed)   │         │
│  └─────────┘     └───────────┘     └──────────────────┘         │
│       │                │                                         │
│       │                │(拒绝)                                    │
│       │           ┌────▼─────┐                                   │
│       └──────────▶│  已拒绝    │                                   │
│                   │ (rejected)│                                   │
│                   └──────────┘                                   │
│                                                                  │
│    工程仓也可在申请中状态自行「取消售后」→ 已取消(cancelled)          │
└─────────────────────────────────────────────────────────────────┘
```

### 各状态定义

| 状态值 | 显示名称 | 含义 | 供应商可操作 |
|--------|---------|------|------------|
| `applying` | 申请中 | 工程仓发起售后申请，待供应商审核 | ✅ 审核（通过/拒绝） |
| `approved` | 审核通过 | 供应商审核通过，待补发 | ✅ 补发商品 |
| `completed` | 已完成 | 补发完成，流程终止 | ❌ |
| `rejected` | 已拒绝 | 供应商拒绝售后申请 | ❌ |
| `cancelled` | 已取消 | 工程仓主动取消售后申请 | ❌ |

> 与仓库端的差异：
> - 仓库端有 `pending`（待审核）+ `waiting`（待补发）两个中间状态，供应商端简化为 `applying → approved` 
> - 供应商端**不需要**质量售后类型，只有物流售后
